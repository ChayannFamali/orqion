# Участие в разработке orqion

Спасибо за интерес к проекту. Здесь — правила, которые позволяют принять
вклад быстро и без лишних кругов.

## С чего начать

- Ошибки и идеи — в [Issues](https://github.com/ChayannFamali/orqion/issues).
  Перед созданием новой проверьте поиск по существующим.
- Уязвимости не публикуйте в issues — порядок описан в
  [SECURITY.md](SECURITY.md).
- За значительные изменения (новая подсистема, изменение поведения) лучше
  сначала открыть issue и обсудить, чем сразу присылать большой PR.

## Окружение разработчика

- Python 3.12, Node.js 20+.
- Бэкенд:

```bash
python -m venv .venv
.venv\Scripts\activate        # Windows; на Linux/macOS — source .venv/bin/activate
pip install -e ".[dev]"
```

- Фронтенд:

```bash
cd frontend && npm ci
```

## Ветки и коммиты

- Ветка от `main`: `feat/<короткое-имя>`, `fix/<короткое-имя>`,
  `docs/<короткое-имя>`.
- Один коммит — одна логическая правка.
- Формат сообщения коммита:

```
<тип>: <описание в повелительном наклонении>
```

Типы: `feat`, `fix`, `docs`, `test`, `refactor`, `chore`.
Примеры: `feat: ограничение размера загружаемого файла`,
`fix: восстановление сборки индекса после перезапуска`.

## Обязательные проверки перед PR

CI выполняет тот же набор; прогоните его локально, иначе PR зависнет на
красных джобах.

Бэкенд (из корня репозитория):

```bash
ruff check backend/
ruff format --check backend/
python -m mypy                # строгий режим, конфигурация в pyproject.toml
python -m pytest backend/tests -q
```

Фронтенд (из `frontend/`):

```bash
npx tsc --noEmit
npx vitest run
npm run build
```

Если менялся API (схемы, роуты) — пересоберите типы фронтенда и проверьте
синхронность:

```bash
python backend/scripts/export_openapi.py
cd frontend && npm run gen:types
```

## Новые зависимости

Только с разрешительной лицензией: MIT, Apache-2.0, BSD, ISC.
GPL, AGPL, SSPL, BUSL и подобные — не принимаются: CI проверяет лицензии
всех зависимостей и упадёт на запрещённой. Если пакет определяет лицензию
как «неизвестная», добавьте его в `backend/scripts/license_allowlist.py`
со ссылкой на источник лицензии.

## Тесты

Новое поведение сопровождается тестами: юнит-тесты в
`backend/tests/unit`, API-поведение — в `backend/tests/integration`,
интерфейс — рядом с существующими тестами компонентов (`frontend`).
Фикс без регрессионного теста — почти всегда недоделанный фикс.

## Вклад с помощью AI-агентов

Использование AI-агентов (генерация кода, рефакторинг, черновики тестов)
допускается при трёх условиях:

1. **Раскрытие.** В описании PR укажите, что изменения созданы или
   дополнены с помощью AI-агента, и какого именно (например, «дополнено с
   помощью Qwen Code»). PR без раскрытия может быть закрыт.
2. **Человеческое ревью обязательно.** Перед мержем изменения проверяет
   человек. AI-агент не может одобрить или слить собственный PR —
   аппрув всегда от человека-участника.
3. **Маркировка коммитов.** Коммиты, созданные или доработанные
   AI-агентом, помечаются трейлером в сообщении коммита:

   ```
   Assisted-by: <имя агента>
   ```

Ответственность за содержимое PR несёт участник, который его открыл,
независимо от того, кто или что писало код.
