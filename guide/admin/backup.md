# Резервные копии и восстановление

Резервная копия — один архив `.tar.gz` со снимком базы данных, файлов
документов и векторного хранилища. Поддерживается профиль `minimal`
(SQLite + встроенное векторное хранилище + локальная папка файлов).

## Создание копии

Остановите сервер или убедитесь, что индексация не идёт, затем:

```bash
python backend/scripts/backup.py --output /путь/для/копий
```

Команда печатает путь к архиву, размер и состав снимка.

Замечания:

- Снимок базы делается атомарно (работа сервера не блокируется), но
  копия во время активной сборки индекса может оказаться несогласованной
  между базой и векторами. Такое восстановление лечится пересборкой
  индекса корпуса.
- Секретный ключ шифрования в архив **не входит**. При восстановлении на
  другом сервере без того же ключа сохранённые ключи провайдеров
  прочитать не удастся — их нужно будет ввести заново в интерфейсе.

## Восстановление

На пустом сервере (создана схема, нет пользовательских данных):

```bash
python backend/scripts/restore.py --input /путь/к/архиву.tar.gz
```

Проверка без записи: добавьте `--dry-run`. Восстановление поверх сервера
с данными отказывает без явного `--force` — перезапись существующих
данных только сознательно:

```bash
python backend/scripts/restore.py --input архив.tar.gz --force
```

После восстановления запустите `orqion serve`. Если снимок делался во
время сборки индекса и поиск работает неполно — пересоберите индекс
корпуса.

## Регулярность

Настройте периодический запуск `backup.py` средствами планировщика вашей
системы. Храните копии вне машины с сервером.
