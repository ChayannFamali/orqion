# Агенты: профили, скиллы, серверы инструментов

Три сущности отвечают за разные вещи:

| Сущность | Раздел интерфейса | Право | Что задаёт |
|---|---|---|---|
| Профиль агента | **Агенты** | `manage_agents` | какую модель и какой скилл использует диалог |
| Скилл | **Скиллы** | `manage_skills` | дополнительные инструкции и разрешённый набор инструментов |
| Сервер инструментов | **Серверы инструментов** | `manage_mcp_servers` | какие внешние инструменты доступны в прогоне |

Ни одна из трёх способностей не входит во встроенные роли: по умолчанию
разделы доступны только администратору. Чтобы делегировать настройку,
добавьте способность политике роли в разделе **Роли**.

Раздел **Агенты** при этом виден всем вошедшим: начать диалог от профиля —
не администраторское действие. Список профилей для выбора и список
скиллов для выбора доступны всем вошедшим (только включённые записи и
только поля, нужные для выбора). Каталог с полными полями, включая
отключённые записи, — только с соответствующим правом: без него каталог и
записи не находятся.

Установка:

```bash
pip install orqion[agent,mcp]
```

Агентный прогон требует дополнение `agent`; внешние инструменты —
дополнение `mcp`. Без них каталоги в интерфейсе работают, а прогон
сообщает о недоступности явно.

## Профили агентов

Поля формы создания профиля:

- **Имя** (до 64 символов) — отображаемое; ссылкой служит идентификатор,
  поэтому переименование не ломает существующие диалоги и записи аудита.
- **Описание** (до 512 символов, необязательно).
- **Модель** — обязательна; список содержит только модели с поддержкой
  инструментов. Профиль с непригодной моделью сервер отклоняет при
  создании, а не сохраняет нерабочим.
- **Скилл** (необязательно) — список содержит только включённые скиллы;
  вариант «Без скилла» оставляет прогон с базовой инструкцией и полным
  набором инструментов роли.
- **Состояние** — новый профиль создаётся включённым; включение и
  выключение делается кнопкой в карточке профиля.

Профиль фиксирует конфигурацию: диалог, созданный от профиля, не может
переопределить модель или скилл — такая попытка отклоняется с кодом
`agent_profile_conflict`. Отключённый профиль исчезает из списка выбора,
а запрос с ним отклоняется кодом `agent_profile_not_available` вместо
тихого отката к произвольной модели: иначе закреплённую администратором
конфигурацию можно было бы обойти. Отключённый скилл в профиле — та же
логика: профиль с ним неработоспособен, поэтому привязать его нельзя.

Лимит — 50 профилей на рабочую область.

### Диалоги профиля

По профилю доступен список его диалогов: число запросов, расход токенов,
стоимость и время последней активности. Это **только метаданные**:
содержимое переписки не отдаётся никому, даже с правом `manage_agents`.
Заголовок диалога — производное от первого сообщения, поэтому заполнен
только для собственных диалогов; у чужих он пустой.

Охват выдачи виден в ответе: `own` — только свои диалоги (без права),
`workspace` — все диалоги рабочей области (с правом `manage_agents`).

## Скиллы

Скилл — декларативный пакет настроек прогона, исполняемого содержимого в
нём нет. Поля формы:

- **Имя** (до 64 символов) и **Описание** (до 512 символов, необязательно).
- **Инструкции агенту** (необязательно) — дописываются к базовым правилам
  агента, а не заменяют их. Предел — 8192 символа.
- **Инструменты** — разрешённый набор, по одному имени на строку; имя
  внешнего инструмента указывается как `<имя_сервера>.<имя_инструмента>`.
  **Пустой список означает ноль инструментов**, а не «не сужать»: форма
  показывает об этом предупреждение. Скилл только сужает доступный набор и
  никогда его не расширяет.
- **Максимум токенов ответа** (необязательно) — применяется, только если в
  диалоге не задано своё значение.
- **Состояние** — новый скилл создаётся включённым; включение и выключение
  делается кнопкой в карточке скилла.

Имена инструментов при сохранении проверяются только по формату: не пустое,
без пробелов и управляющих символов, до 128 символов; повторы убираются с
сохранением порядка. Состав реестра не проверяется намеренно: сервер может
быть зарегистрирован позже скилла, а инструмент может исчезнуть вместе с
сервером — в прогоне это деградация (инструмент не вызывается), а не отказ
сохранить скилл.

Запрошенный несуществующий или отключённый скилл даёт явную ошибку
`skill_not_available`, а не тихий прогон без него.

Лимит — 50 скиллов на рабочую область.

## Серверы инструментов

Подключение внешних инструментов идёт по протоколу Model Context Protocol.
Поля формы:

- **Имя** — строчные латинские буквы, цифры, дефис и подчёркивание,
  начинается с буквы, до 64 символов, **без точки**. Имя становится
  неймспейсом инструментов сервера, поэтому переименование не
  поддерживается: оно меняло бы имена инструментов, видимые модели.
- **Адрес** — только `http://` или `https://` с явным хостом. Локальные
  процессы сервер не запускает.
- **Секрет** (необязательно) — принимается при записи и никогда не
  возвращается в ответах; в каталоге виден только факт его наличия, а поле
  при изменении оставьте пустым, чтобы секрет не менять. Хранится
  зашифрованным.
- **Состояние** — новый сервер регистрируется включённым.

Таймауты задаются переменными окружения: `ORQION_MCP_DISCOVERY_TIMEOUT`
(по умолчанию 10 секунд на обнаружение инструментов) и
`ORQION_MCP_CALL_TIMEOUT` (по умолчанию 30 секунд на вызов).

Признак деструктивности инструмента заявляет сам сервер в аннотациях
инструмента — в настройках orqion он не переопределяется.

## Ограничения прогона

Задаются переменными окружения:

| Переменная | По умолчанию | Что ограничивает |
|---|---|---|
| `ORQION_AGENT_MAX_STEPS` | 10 | число обращений к модели за прогон |
| `ORQION_AGENT_MAX_TOKENS_PER_RUN` | 100 000 | суммарный расход токенов за прогон |

Это предохранитель поверх обычных лимитов политики роли (токены на запрос,
месячный бюджет, частота запросов). При исчерпании прогон прерывается
ошибкой `agent_run_limit_exceeded` с указанием достигнутого предела.

## Безопасность

- **Деструктивные вызовы** не выполняются сразу: прогон останавливается и
  ждёт подтверждения пользователя. Признака «доверенного» инструмента в
  схемах нет вовсе — обойти подтверждение полем запроса нельзя.
- **Классы данных.** Внешние инструменты доступны только для содержимого
  ниже К2: для корпусов К2 и К3 весь набор внешних инструментов
  отклоняется до любого обращения к серверам, факт пишется в журнал
  аудита. Запрос защищённого корпуса к внешней модели отклоняется
  отдельной проверкой и фиксируется действием
  `security.data_class_violation`.
- **Отказ сервера не роняет прогон.** Если инструменты сервера не
  обнаружились, они скрываются из реестра прогона, а факт пишется в журнал
  аудита; остальные серверы и встроенные инструменты продолжают работать.
  Ошибка отдельного вызова возвращается модели как результат инструмента.

## Журнал аудита

| Действие | Когда пишется |
|---|---|
| `agent_skill.changed` | создание, изменение, удаление скилла — без текста инструкции, только её длина |
| `agent_profile.changed` | создание, изменение, удаление профиля |
| `agent.conversation.stop_requested` | запрос остановки прогона (повторное нажатие записи не плодит) |
| `agent.conversation.stopped` | факт остановки прогона |
| `agent.tool.confirmation` | ожидание подтверждения деструктивного вызова |
| `agent.tool.search_corpus` | вызов встроенного поиска по корпусу |
| `agent.tool.mcp` | вызов внешнего инструмента — с решением по классу данных и ошибкой, если она была |
| `mcp.tools.blocked` | внешние инструменты отклонены классом данных |
| `mcp.server.unavailable` | инструменты сервера не обнаружились |
| `security.data_class_violation` | запрос защищённого корпуса к внешней модели |

Изменения самого реестра серверов инструментов в журнале аудита не
фиксируются — только события прогона.
