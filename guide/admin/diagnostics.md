# Диагностика окружения

Раздел **Диагностика** показывает состояние окружения, в котором работает
сервер. Раздел **только читает**: он ничего не устанавливает, не обновляет
и не перезапускает, в том числе драйверы.

Право на раздел — способность `view_diagnostics`. Во встроенные роли она не
входит, поэтому по умолчанию раздел видит только администратор; чтобы
делегировать его, добавьте способность политике роли в разделе **Роли**.
Без права раздел недоступен и по адресу.

## Разделы страницы

### GPU (NVIDIA)

По каждой видеокарте — её имя, занятая и общая память видеокарты (в MiB),
температура и загрузка, а над списком — версия драйвера. Метрики читаются
через служебную программу производителя (`nvidia-smi`); если она не найдена
или её вывод не разбирается, блок честно показывает «Недоступно» с причиной,
а не пустые нули. Отдельная метрика, которая не прочиталась, показывается
как «недоступно» — остальные при этом выводятся. Рядом может быть ссылка на
страницу драйверов производителя; установка выполняется средствами
операционной системы.

### Хост

Операционная система и её версия, версия Python, время непрерывной работы
сервера и момент запуска процесса. Если сервер собран без полного запуска
(например, в тестах или в команде импорта), время работы показывается как
«неизвестно», а не как ноль.

Ниже — **Свободное место** по точкам хранения на этом хосте:

| Том | Показывается, когда |
|---|---|
| Хранилище документов | документы хранятся в локальном каталоге, а не в S3 |
| Векторный индекс | индекс ведёт встроенное векторное хранилище, а не внешний Qdrant |
| База данных | база — файл SQLite, а не сетевая СУБД |

Пункт отсутствует, когда данные лежат вне этого хоста: показать вместо него
свободное место локального тома значило бы выдать чужое хранилище за своё.

На свежей установке каталога хранилища или файла базы ещё нет — место
измеряется по ближайшему существующему предку пути, и фактически
измеренный путь показывается отдельно.

### Внешние сервисы

Список провайдеров рабочей области: вид провайдера и его роль («модель»
или «эмбеддинги»), адрес, два счётчика моделей — сколько зарегистрировано и
сколько доступно по результату проверки, — и время последней проверки.

Статус берётся из результата **последней плановой проверки**, которая
выполняется периодически в фоне; сам раздел запросов к провайдерам не
делает. Отсюда состояния:

| Состояние | Что означает |
|---|---|
| доступен | проверка прошла, есть доступные модели |
| нет доступных моделей | проверка прошла, но моделей нет или ответ пуст |
| ещё не проверялся | плановая проверка ещё не выполнялась — сразу после запуска сервера это нормальное состояние |
| отключён | провайдер выключен, плановая проверка его не опрашивает |
| не настроен | встраивания направлены через провайдера, но свести их к нему не удалось: алиас модели не задан или модель с таким алиасом не найдена |

Интервал плановой проверки — `ORQION_PROBE_INTERVAL_SECONDS` (по умолчанию
900 секунд). Планировщик спит перед первым прогоном, поэтому сразу после
запуска сервера все провайдеры будут в состоянии «ещё не проверялся».
Проверить провайдера вручную можно кнопкой «Проверить» в разделе
**Провайдеры**.

Отдельного состояния «отказ» нет: причина неудачи проверки не сохраняется,
поэтому «провайдер не ответил» и «ответил пустым списком» неразличимы и
показываются как «нет доступных моделей».

### Локальные компоненты

| Компонент | Что проверяется |
|---|---|
| Эмбеддинги (локальный пакет) | установлен ли пакет локальных встраиваний; если встраивания идут через провайдера — «не используется» |
| Реранкинг (локальный пакет) | установлен ли пакет; без него поиск штатно работает без переранжирования |
| sqlite-vec (векторный поиск) | грузится ли векторное расширение; при внешнем Qdrant — «не используется» |
| Векторное хранилище | файл индекса: существует и читается; при внешнем Qdrant — «не используется» с адресом сервера |
| Хранилище документов | каталог документов; при S3 — «не используется» с именем корзины |
| База данных | файл SQLite; при сетевой СУБД — «не используется» |

Состояний три: **доступно**, **недоступно** и **не используется**. Третье —
не неисправность: компонент в этой конфигурации не нужен, ещё не создан,
либо его проверка потребовала бы сетевого запроса, которого в разделе нет.
Причина и пояснение пишутся под названием.

Веса моделей не проверяются: переранжирование загружает их при первом
поиске, поэтому для него проверяется только наличие пакета. То же для
локальных встраиваний — их модель и веса загружаются при первом обращении.

## Что не отдаётся наружу

- Строка соединения с базой данных не показывается — для сетевой СУБД
  виден только её тип. В ней может быть пароль.
- Секреты провайдеров и серверов инструментов в ответ не попадают.
- Отсутствующий файл или каталог показывается как «ещё не создан» с
  пояснением, когда он появится, а не как ошибка.
