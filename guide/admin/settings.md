# Служебные настройки

Часть служебных настроек редактируется в интерфейсе: раздел **Настройки** →
вкладка **Общие**. Остальные задаются переменными окружения с префиксом
`ORQION_`.

## Права

Чтение настроек доступно всем вошедшим пользователям: реестр не хранит
секретов, поэтому «закрытого» списка чтения нет. Право на изменение
определяется способностью `manage_settings` (или полным доступом роли).
Пользователь без права видит поля только для чтения, а попытка записи
отклоняется сервером: существование настройки и требование к праву при
этом не раскрываются.

Параметры поиска по документам — отдельная вкладка, право на их изменение
даёт способность управления корпусами (`manage_corpora`).

## Ключи реестра

| Ключ | Категория | Диапазон | Переменная окружения | По умолчанию |
|---|---|---|---|---|
| `session_ttl_days` | Сессии и безопасность | 1–365 | `ORQION_SESSION_TTL_DAYS` | 7 |
| `max_upload_size_mb` | Файлы и хранение | 1–1024 | `ORQION_MAX_UPLOAD_SIZE_MB` | 50 |
| `allowed_upload_extensions` | Файлы и хранение | список, до 1024 символов | `ORQION_ALLOWED_UPLOAD_EXTENSIONS` | `.pdf,.docx,.pptx,.xlsx,.py,.cpp,.ts,.go,.java,.sql,.md,.txt` |
| `default_temperature` | Модель по умолчанию | 0–2 | `ORQION_DEFAULT_TEMPERATURE` | 0.7 |

Верхняя граница размера файла не произвольная: разбор документа держит
файл целиком в памяти, поэтому значение выше предела исчерпало бы память
сервера. Граница температуры тоже рабочая, а не «на глаз»: API моделей
принимают 0–2.

Каждое расширение указывается с точкой — совпадение проверяется по концу
имени файла, поэтому `pdf` без точки не совпал бы ни с одним файлом и
выглядело бы как сломавшаяся загрузка. Запись через интерфейс без точки
отклоняется; в переменной окружения такой элемент приводится к виду с
точкой и помечается предупреждением в журнале — опечатка в env не должна
ломать загрузку целиком. Пустая строка запрещает загрузку всех файлов:
пустой список означает ноль, а не «всё». Пробелы вокруг элементов списком
не считаются.

## Приоритет значений

Значение резолвится в момент запроса:

1. **Записанное в интерфейсе** — если значение сохранено, действует оно.
2. **Переменная окружения** — до первой записи env задаёт значение по
   умолчанию.

Интерфейс показывает источник каждого значения: **изменено** или **по
умолчанию**. Перезапуск сервера не требуется ни при записи, ни при
изменении env до первой записи.

Изменение срока жизни сессии не затрагивает уже выданные сессии: они
доживают свой срок, новое значение действует на сессии, созданные после
изменения.

Лимиты загрузки действуют на оба пути попадания файла в корпус — загрузку
в интерфейсе и импорт git-репозитория из командной строки. Для импорта
приоритет такой: флаг команды > настройка рабочей области > переменная
окружения; команда печатает действующее значение вместе с его источником.

Температура по умолчанию распространяется на чат, ответы по документам и
агентные прогоны. Явное значение температуры в запросе к API побеждает
настройку. Проверка доступности провайдера выполняется при температуре 0
и настройке не подчиняется.

## Валидация

Значение проверяется на сервере, а не только в интерфейсе: неверное
значение отклоняется с кодом `422` и пояснением на русском (что ожидалось
и в каком диапазоне). Неподписанное поле в запросе тоже отклоняется, а не
игнорируется молча.

## Журнал аудита

Каждая успешная запись фиксируется в журнале аудита действием
`settings.changed` со старым и новым значением; ключ настройки и исполнитель
видны в записи. Повторная запись того же значения тоже оставляет запись —
аудит отвечает на вопрос «кто обращался к настройке», а не «изменилось ли
значение». Изменение параметров поиска фиксируется действием
`rag_settings.changed`.

## Что в реестр не входит

- **Ограничения агентного прогона** — число шагов и расход токенов за
  прогон задаются только переменными окружения `ORQION_AGENT_MAX_STEPS`
  (по умолчанию 10) и `ORQION_AGENT_MAX_TOKENS_PER_RUN` (по умолчанию
  100 000).
- **Личные настройки пользователя** (раздел **Профиль**) принадлежат
  владельцу: переменными окружения не задаются, в журнал аудита не
  попадают, чужие значения недоступны.
- **Секреты** — ключи провайдеров и серверов инструментов хранятся
  зашифрованными и в ответах не возвращаются.

## Добавление новой настройки

Описание ключа (название, пояснение, категория, модель значения, право на
запись) живёт в коде; в базе хранится только факт записанного значения.
Поэтому новая настройка не требует миграции и изменения интерфейса:
вкладка **Общие** рисуется из ответа API, а категории становятся группами
полей. Ключ добавляется в реестр и подхватывается без перезапуска.
