# Подключение локальных моделей (LM Studio / Ollama)

orqion не выполняет инференс сам — он подключается к серверу моделей.
Локальный сервер моделей: [LM Studio](https://lmstudio.ai) или
[Ollama](https://ollama.com). Любой другой сервер с OpenAI-совместимым API
тоже подойдёт (тип провайдера «внешний»).

## Вариант 1. LM Studio

1. В LM Studio загрузите модель (вкладка моделей) и запустите локальный
   сервер (вкладка «Local Server»). По умолчанию он слушает
   `http://127.0.0.1:1234/v1`.
2. В orqion откройте раздел **Провайдеры** → добавить провайдер:
   тип **LM Studio**, адрес `http://127.0.0.1:1234/v1`.
3. Сохраните. Подключение проверяется автоматически; раздел
   **Диагностика** показывает состояние каждого провайдера и модели.

## Вариант 2. Ollama

1. Установите и запустите Ollama (`ollama serve`), загрузите модель:
   `ollama pull <имя модели>`.
2. В orqion: раздел **Провайдеры** → добавить провайдер: тип **Ollama**,
   адрес `http://127.0.0.1:11434` (по умолчанию).

## Реестр моделей

После подключения провайдера откройте его реестр моделей. Имя модели должно
совпадать с тем, что отдаёт сервер моделей (для LM Studio — список
`http://127.0.0.1:1234/v1/models`). Отметьте модели, с которыми будете
работать: для чата и отдельно — для встраиваний (см. ниже).

## Эмбеддинги (встраивания) для поиска по документам

Поиск по корпусу использует модель встраиваний. Два режима — переключаются
переменными окружения (файл `.env` рядом с местом запуска, все настройки
имеют префикс `ORQION_`):

**Через провайдера (проще).** Если ваш сервер моделей умеет считать
эмбеддинги (в LM Studio — загрузите модель встраиваний, например
`text-embedding-bge-m3`, и включите её в реестре):

```env
ORQION_EMBEDDINGS_BACKEND=provider
ORQION_EMBEDDINGS_MODEL_ALIAS=<имя модели встраиваний из реестра>
```

**Локально.** Установите дополнительную зависимость и используйте модель
по умолчанию:

```bash
pip install -e ".[full]"
```

```env
ORQION_EMBEDDINGS_BACKEND=local
ORQION_EMBEDDINGS_MODEL=BAAI/bge-m3
```

Локальный режим при первом запуске скачивает модель и требует заметного
объёма памяти.

После изменения `.env` перезапустите сервер (`orqion serve`).

## Проверка

Раздел **Диагностика** показывает состояние окружения: видеокарты (если
установлен `nvidia-smi`), операционную систему, версию Python, время работы
сервера и свободное место на томах, где лежат документы, векторный индекс и
база данных. Отдельно — внешние сервисы (провайдеры моделей) и локальные
компоненты (пакет эмбеддингов и реранкинга, векторное расширение,
хранилища).

Раздел только читает: он не устанавливает и не обновляет ничего, в том числе
драйверы. Кнопка запуска проверки провайдера находится в разделе
**Провайдеры**.

Статус провайдера в диагностике берётся из результата последней проверки, а
не измеряется заново при открытии страницы. Поэтому сразу после запуска
сервера там может быть «ещё не проверялся»: плановая проверка выполняется
периодически в фоне (интервал задаётся `ORQION_PROBE_INTERVAL_SECONDS`).
Чтобы не ждать, запустите проверку вручную в разделе **Провайдеры**.

Если проба модели проваливается — проверьте, что модель загружена в сервере
и её имя в реестре совпадает с именем на сервере. Текст ошибки показывает
раздел **Провайдеры**.

## Типичные проблемы

- **Модель не найдена** — имя в реестре orqion не совпадает с именем,
  которое отдаёт сервер моделей (`/v1/models`). Исправьте имя в реестре.
- **Провайдер недоступен** — сервер моделей не запущен или слушает другой
  адрес/порт.
- **Сборка индекса не стартует** — не настроен режим эмбеддингов (см. выше)
  либо модель встраиваний не отвечает.
