# Оценка качества поиска

Оценка отвечает на вопрос «насколько хорошо индекс находит нужные
документы» измерением, а не впечатлениями. Рекомендуемый порядок работы:
собрать версию индекса → прогнать оценку → активировать, если результат
устраивает.

## Из чего состоит оценка

- **Набор оценки** — список контрольных вопросов по документам корпуса.
  Для каждого вопроса указываются документы, в которых содержится ответ.
- **Прогон** — выполнение набора на выбранной версии индекса. Каждый
  вопрос прогоняется через поиск, результаты сравниваются с ожидаемыми
  документами.

## Создание набора

Корпус → **Оценка качества** → «Создать набор». Добавьте вопросы и для
каждого отметьте документы корпуса, содержащие ответ. Хороший набор —
5–15 вопросов, покрывающих разные документы и разные формулировки.

## Прогон

Внутри набора — **Прогоны** → «Запустить»: выберите версию индекса и
подтвердите. Прогон считается метрики:

- **recall@1 / @3 / @5 / @10** — доля вопросов, где нужный документ
  попал в первые 1 / 3 / 5 / 10 результатов поиска;
- **MRR** — насколько высоко в среднем оказывается первый нужный документ;
- **доля ответов с источниками** — у скольких ответов есть хотя бы один
  фрагмент-источник;
- **доля честных отказов** — для вопросов без совпадений модель ответила
  отказом, а не выдумкой.

## Сравнение версий

Прогон можно сравнить с предыдущим: таблица «Сравнение метрик» показывает
значение «было», «стало», разницу и направление изменения по каждой
метрике. Так принимается решение об активации: собрали новую версию,
прогнали оценку, сравнили с прошлой — и активировали только если стало
лучше.

Оценка не блокирует активацию: активировать версию можно и без прогона —
но интерфейс предупредит, что успешного прогона нет.

## Практика

- Держите набор актуальным: добавили документы — добавьте вопросы про них.
- Прогоняйте оценку на каждой новой версии перед активацией.
- Если метрика упала — не активируйте; откат версии всегда доступен, но
  проще не переключаться.
