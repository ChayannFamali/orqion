# Журнал изменений

Здесь записываются все значимые изменения проекта.

Формат основан на [Keep a Changelog 1.1.0](https://keepachangelog.com/ru/1.1.0/),
версии следуют [семантическому версионированию](https://semver.org/lang/ru/).

До первого фактического опубликованного выпуска (тега) версия за каждую
фичу не поднимается — изменения копятся в разделе текущей версии.
Дисциплина поминорного бампа за фичу и патч-бампа за исправление начинает
действовать после первого опубликованного тега.

## [0.1.0] — ещё не выпущен

Первый публичный выпуск: сводная запись обо всём, что реализовано к нему.
Тег не создан и пакет не опубликован, раздел пополняется по мере готовности
функций. Сводка впервые составлена 2026-08-30, последние записи — 2026-09-12.

### Добавлено

- **Чат и модели.** Диалоги с потоковыми ответами, выбор модели по
  политикам ролей и правилами маршрутизации, ручной выбор модели в новом
  диалоге, оценка занятости окна контекста, режим рассуждения для
  поддерживающих моделей, перенаправление вопросов, поиск по диалогам.
- **Агентные диалоги, внешние инструменты, скиллы и профили агентов**
  (2026-09-03…09-09). Агентный режим диалога: модель сама обращается к
  поиску по корпусу и к внешним инструментам, прогон идёт циклом
  «модель → инструменты → модель», каждый шаг виден в ленте шагов;
  ограничения на число шагов и расход токенов за прогон. Подключение
  внешних инструментов по протоколу Model Context Protocol: серверы
  регистрирует администратор, секрет хранится зашифрованным,
  доступность проверяется при опросе, сбой одного сервера не прерывает
  прогон; вынос данных во внешние сервисы отклоняется для защищённых
  классов до обращения к серверу, а деструктивный вызов останавливает
  прогон и ждёт подтверждения пользователя. Скиллы: именованные пакеты
  настроек агентного прогона — фрагмент системной инструкции и
  разрешённый набор инструментов; скилл сужает набор инструментов и
  никогда его не расширяет, пустой набор означает прогон без
  инструментов, а несуществующий или отключённый скилл — явная ошибка
  запроса, а не тихий прогон без него; изменения скиллов фиксируются в
  журнале аудита без текста инструкции. Профили агентов:
  переиспользуемая конфигурация диалога «модель + скилл»; каталог
  профилей ведёт администратор, список выбора при старте диалога
  доступен всем пользователям. Отключённый профиль исчезает из выбора,
  а запрос с ним отклоняется явно, без отката к произвольной модели. По
  профилю доступен список его диалогов с расходом токенов — только
  метаданные: содержимое переписки не отдаётся никому, а заголовок
  заполняется лишь для собственных диалогов. Прогон можно остановить:
  запрос принимается сразу, текущий шаг дорабатывается, следующий не
  начинается, в диалоге появляется явный ответ об остановке. Агентный
  режим, внешние инструменты и граф связей документов устанавливаются
  отдельными дополнениями и без них сообщают о недоступности явно, а не
  падают.
- **Подключение провайдеров.** Регистрация провайдеров моделей: локальные
  сервисы (форматы совместимых интерфейсов), облачные площадки; локальные
  и внешние модели, загрузка весов из каталогов, проверка доступности.
- **Корпуса и поиск по документам.** Загрузка документов (одиночная и
  пакетная), источники из git-репозиториев, сборка версий индекса с
  фиксацией результатов и откатом, гибридный поиск (векторный +
  полнотекстовый) с реранкингом, настройки качества поиска (порог
  релевантности, максимум фрагментов и число групп графа документов),
  граф связей кода, граф связей документов (семантические группы),
  сохранённые шаблоны промптов.
- **Доступ и роли.** Роли и политики доступа, журнал аудита, удержание
  данных, защита данных при выносе во внешние сервисы, встроенные
  детекторы чувствительных данных, внешние поставщики учётных записей.
- **Настройки** (2026-09-11…09-12). Служебные настройки рабочей области
  редактируются в интерфейсе: **Настройки → Общие** — срок жизни
  сессии, максимальный размер загружаемого файла и разрешённые
  расширения, температура генерации по умолчанию. У каждого значения
  видно, изменено оно или осталось по умолчанию; значение проверяется на
  сервере, применяется сразу, без перезапуска, а успешное изменение
  фиксируется в журнале аудита. Право на изменение определяется ролью:
  без него настройка помечается недоступной для правки, а попытка
  записи отклоняется. Лимиты загрузки действуют на оба пути попадания
  файла в корпус — загрузку в интерфейсе и импорт из командной строки,
  где флаг команды имеет приоритет над настройкой. Температура по
  умолчанию распространяется на чат, ответы по документам и агентные
  диалоги; явная температура в запросе к API побеждает настройку.
  Изменение срока жизни сессии не затрагивает уже выданные сессии — они
  доживают свой срок. Личные настройки пользователя вынесены в раздел
  **Профиль**: способ отправки сообщения (`Enter` или `Shift+Enter`) и
  тема оформления. Личная настройка принадлежит своему владельцу:
  доступна независимо от служебных прав, чужие значения не читаются и
  не перезаписываются, в журнал аудита не попадают.
- **Оценка качества поиска.** Наборы ожидаемых ответов, метрики
  (полнота выдачи и среднее взаимное ранжирование), запуск оценки и
  отказов.
- **Эксплуатация.** Экспорт диалогов, журнала аудита и аналитики,
  экспорт и импорт конфигурации ролей и правил, резервное копирование
  и восстановление, резервная модель при недоступности основной,
  автоматическая генерация заголовков диалогов.
- **Диагностика окружения** (2026-09-12). Раздел **Диагностика**
  показывает состояние окружения: видеокарты (если установлена
  служебная программа производителя), операционную систему, версию
  Python и время непрерывной работы сервера, свободное место на томах,
  где лежат документы, векторный индекс и база данных, внешние сервисы
  (провайдеры моделей) и локальные компоненты — пакеты встраивания и
  переранжирования, векторное расширение, файловое и векторное
  хранилища, база данных. Раздел только читает: ничего не устанавливает
  и не обновляет, в том числе драйверы. Статус провайдера берётся из
  результата последней плановой проверки, а не измеряется при открытии
  страницы, поэтому сразу после запуска сервера возможно состояние
  «ещё не проверялся». Компонент, который в данной конфигурации не
  используется, отмечен как неиспользуемый, а не как неисправный: том
  базы данных показывается только для локального файла, при сетевой
  СУБД, внешнем векторном хранилище или объектном хранилище документов
  чужое хранилище не выдаётся за локальное. Адрес соединения с СУБД
  наружу не отдаётся — только её тип.
- **Документация и лицензия.** Пользовательское и администраторское
  руководства, правила участия, порядок сообщения об уязвимостях.
  Лицензия выпуска — BUSL-1.1 (лицензия делового исходного кода):
  свободно, включая производственное использование, для частных лиц и
  организаций до 500 сотрудников; 26 августа 2028 года произведение
  переходит под Apache-2.0.
